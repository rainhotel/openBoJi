# v0.3：对话就是任务入口

本轮授权：用户于 2026-10-20 明确要求继续迭代、真实 DeepSeek 调试、Agent 一键创建、减少标签和修复视图/工具问题。延续产品分析后实施的工作方式；针对现有体验修补，不替换 Pi 内核或重建数据。

## 已确认的问题

1. 待处理草稿禁用发送，不能继续补充或改正；创建任务必须打开另一层核对页再保存。
2. 日历显示排序/分组控件，实际日列表重新按时间排序、忽略用户选择。
3. 新建默认展示十余个字段；顶部新建未继承选中日期。
4. 本地保存尚未完成就关闭编辑页，失败后没有原位纠错入口。
5. 四底栏、四角色与重复的创建入口增加理解负担。保存的视图不能管理删除，也不能恢复搜索条件。

## 本轮交付规则

- 主导航为「助手 / 日程 / 积累」。领域由助手识别，不要求先选角色。今日摘要仍可在日程查看。
- 用户明确要求创建的任务，Agent 结构化生成并经本地校验后直接保存，显示真实结果和撤销；歧义日期先追问。只修改用户指定的已有任务，不覆盖其他安排。
- 实际记录与长期记忆保留聊天内的一键确认，可展开编辑。草稿不阻断继续对话；确认前不声称完成。
- 工具只暴露当前授权可用的读取能力；创建工具字段收敛并给合理缺省，已有任务支持显式更新。保留旧 propose_draft 兼容已有 Skill。
- 日历与表格共享任务；排序在所选日期列表生效，表格特有的分组/列设置仅在表格出现。「视图」统一收纳高级操作与已存视图管理。
- 手动新建首屏只保留内容、日期、时间；高级字段折叠；保存成功后才关闭，失败保留输入，防重复点击。
- 密钥只用于用户授权的官方接口，本地调试凭据加密保存于忽略目录，不进入代码、APK、日志或截图。正常测试不默认调用付费模型，云端用例显式开启。

## 验收场景

1. 说「明晚八点练胸四十分钟，提前十分钟提醒」→任务真实出现→日历/表格一致→撤销只撤销本次变更。
2. 连续说「改成后天九点，P1」→更新原任务而非复制；重新进入后保留。
3. 明确日期的考试和复习计划→批量创建、父子关系、时刻、提醒；缺日期不会瞎猜。
4. 「今天练胸七次」+照片→正确数量/附件/唯一任务关联→聊天内一次确认；继续纠正不被草稿锁住。
5. 模型连接、权限关闭、无效工具参数、取消/失败、重复提交→真实反馈且无半成品写入。
6. 新建/修改失败保留字段；选中日期新建；小屏、键盘、横屏；保存/切换/删除视图。

每轮记录发现、修复、自动测试与实际模拟器走查，区分宿主云端协议测试、手机内 Pi→原生工具→真实 API、模拟器与实体手机。

## 实施中发现与修复

- 手动走查确认：保存后任务行可能只露出 3px，Snackbar 遮挡立即完成操作。日历改为默认本周、按需展开整月；保存成功用页面变化和对话回执反馈，去掉遮挡内容的保存 Snackbar。
- 跳转创建结果时清空旧搜索/筛选、切回日历并定位目标日；请求消费后不会覆盖后续手选日期。
- 重复创建比较全部有效字段，字段不同要求通过更新工具处理；父子批次先解析父项，纯重复请求不会误显示旧操作撤销。
- 照片记录数量或标题纠正保留原附件；草稿保存后追加原生生成的事实回执。
- 真实云端首轮通过后，逐张检查截图，发现周视图仍沿用月网格序号，改为真实日号并增加断言；旧任务操作卡片不再一直悬在最新记录下面，改为绑定产生它的那条回复。

最终数字与验证范围见 [验收记录](./implementation-status.md)，以最终复验结果为准。

## 第二轮：失败恢复与反馈收敛

在已通过真实云端和模拟器的版本上继续小范围修补：失败/停止的最后一条消息可重试；WebView 意外关闭后下次请求重建运行时；明确完成但未计时计数的记录保留未知数值，不为通过工具校验臆造分钟或次数。任务完成计次只在无最低时长要求时认可这种明确关联记录。创建结果与草稿只显示非空信息，助手不重复逐项朗读界面卡片。继续用现有工具和表结构，不扩展领域或增加主导航。

- 独立子智能体实际走查发现 360×640 dp、1.3 倍字体的横屏表格没有可见任务行。压缩全局头部和底栏，把「视图」放进横屏单行标题；复测 640×360 dp 下任务行可见高度 62 dp。测试等待布局和旋转动画稳定后再测量及截图，避免把中间帧当验收结果。
- 设置中模型草稿可能含旧的读取权限，造成界面显示与当前工具授权不一致。权限和预算改为读取已生效配置；密钥、模型和思考选项继续从加密草稿恢复。新增真实 UI 回归覆盖该差异。
- 已通过正常 Android 36 回归 43 项、JVM 26 项、Agent JavaScript 10 项；小屏大字体单独运行并人工检查横屏截图。云端用例加入无计量完成场景，具体结果以最终验收文件为准。
